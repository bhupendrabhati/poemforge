# PoemForge — Design Doc

Date: 2026-08-18
Status: Approved (user reviewed the design presented in-session on 2026-08-18)

## Overview

PoemForge is a creative web app that generates short poems and micro-stories from a few simple inputs. It is built for the AWS "Build a Creative App" weekend challenge and runs on AWS Free Tier services (Amazon Bedrock Nova, Lambda, API Gateway, S3), while remaining fully functional for local preview without an AWS account.

## Goal

Make people smile: pick a mood, style, and length, optionally add a topic word, press Generate, and read something unexpectedly delightful. The app must never fail on a generation — if the AI path is unavailable, it falls back to a deterministic creative engine.

## Approach

Hybrid backend (Approach A):

- Frontend calls a single backend endpoint (`POST /api/generate`).
- The backend tries Amazon Bedrock (Nova text model). On any failure (no credentials, region unsupported, throttling, timeout), it silently falls back to a built-in template-based poem engine.
- The exact same generation code runs in the AWS Lambda handler and in a local Express dev server, so local preview exercises the real backend behavior.

## Stack

| Layer | Choice |

| Frontend | Vite + React + TypeScript SPA |

## Generation API

`POST /api/generate`

Request body:

```json
{
  "mood": "happy",
  "style": "haiku",
  "length": "short",
  "topic": "ocean"
}
```

- `mood`: `happy | calm | curious | whimsical | melancholy | epic`
- `style`: `haiku | free-verse | rhyming | limerick | micro-story`
- `length`: `short | medium | long`
- `topic`: optional free-text word/phrase, max 40 chars

Response:

```json
{
  "poem": "lines of generated text...",
  "title": "optional title",
  "usedAi": true
}
```

- `poem`: plain-text multi-line poem or micro-story.
- `title`: generated title where the style supports one (omitted otherwise).
- `usedAi`: `true` if generated by Bedrock, `false` if from the fallback engine.

Validation: unknown enum values or missing fields return `400` with a JSON error body. Server errors return `500` with a friendly JSON error body.

## Generation logic

### Bedrock path

1. Build a prompt from the request (mood, style, length, topic), instructing the model to return strict JSON: `{"title": "...", "poem": "..."}`.
2. Call Bedrock Runtime `InvokeModel` with `amazon.nova-micro-v1:0`, `max_tokens` scaled by length (short 120, medium 200, long 320), `temperature` 0.9.
3. Enforce a 5-second timeout (wrapped around the SDK call).
4. Parse and validate the JSON; on any exception, or invalid/unparseable output, fall through to the engine.
5. Optionally use the `AWS_BEDROCK_MODEL_ID` / `AWS_BEDROCK_REGION` env vars to override the default model/region.

### Fallback engine

- Deterministic template system: per-style line/template lists combined with per-mood word banks.
- Combinatorial variety: multiple templates per style and many word options per mood, sampled with a seeded PRNG.
- Seeding: `generateEngine(inputs, seed)` takes an optional numeric `seed`. When omitted, a random seed is used. The API layer computes `seed = hash(mood|style|length|topic|currentMinuteBucket)` so rapid identical clicks still vary while results stay roughly stable. Tests always pass explicit seeds to assert exact determinism.
- Length scales output size: for line-based styles, short ~4-6 lines, medium ~8-12, long ~14-24; haiku is fixed at 3 lines; micro-story short = 3 sentences, medium = 4-5, long = 6-8. Exact counts per style are defined in the engine implementation.
- Styles map to concrete shapes:
  - haiku: 5-7-5 syllable lines from curated syllable-annotated word banks.
  - rhyming: 4 or 8 lines, AABB rhyme pairs.
  - free-verse: 4-12 free lines assembled from fragments.
  - limerick: classic AABBA 5-line shape.
  - micro-story: 3-5 sentences from story fragment templates.
- Topic word, when provided, is woven into one line/sentence.
- Guaranteed to never return `undefined`, empty, or malformed output.

## Frontend behavior

- One page: pickers for mood/style/length, an optional topic input, and a big Generate button.
- On generate: loading state, then animated reveal (lines fade in sequentially). `usedAi` is shown as a small badge ("sparked by Nova" vs "crafted by hand").
- History: last 12 generations persisted in `localStorage`, clickable to re-show, clearable.
- Copy to clipboard button; share via `navigator.share` when available, clipboard fallback.
- Dark, playful visual theme; responsive layout.
- Fetch wrapper uses `AbortController` with a 12s timeout; network errors show a friendly inline message and keep the previous poem on screen.

## Error handling

- Backend: Bedrock failure/absence/timeout → fallback engine; the endpoint always returns a valid poem or a clear 4xx/5xx JSON error.
- Frontend: timeout / network failure → inline retry message; no crashes.
- Guardrail: strip ANSI/control chars from engine + model output before returning.

## Testing

### Backend (`node:test`)

- Engine: given each mood/style/length combo, output is non-empty, contains no `undefined`, respects length buckets (rough line counts), and the seeded PRNG is deterministic for identical inputs.
- API validation: invalid enum → 400; valid request → 200 with expected JSON shape.

### Frontend (Vitest + Testing Library)

- Renders the page with all pickers.
- Mocking `fetch`, clicking Generate renders a poem and the `usedAi` badge.

## Deployment (documented in README)

1. Backend: `sam build && sam deploy --guided` → prints an API Gateway base URL.
2. Frontend build: `npm run build` with `VITE_API_URL` set to the deployed endpoint, upload `dist/` to an S3 bucket with static website hosting enabled (or behind CloudFront).

## Local preview

- `npm run install` in `frontend/` and `backend/`.
- Start backend: `node backend/src/server.js` (port 3001). Bedrock is used only if valid AWS credentials are configured; otherwise the engine runs.
- Start frontend: `npm run dev` in `frontend/` (port 5173, proxies `/api` to 3001).
- `start.sh` starts both for convenience.

## Out of scope

- Auth, user accounts, multi-user state.
- Image/audio generation.
- Streaming responses.
- Cost optimization beyond Free Tier defaults (no persistent storage, no queueing).
